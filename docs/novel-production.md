# 小说制片初版设计（2.6）

本页保留初版设计供开发对照。当前 3.2 的自动审核、对白账本、镜头密度、声音方案与界面以 [项目制作工作台](production-workbench.md) 和 [使用说明](../使用说明.md) 为准。

## 用户已经确定的方向

输入一章小说，忠于原著、适度影视化。先审核剧本与定稿资产，再自动生成分镜、并行生成视频。每集剪辑时间轴为 120 秒，不要求平台一次生成 120 秒。

## 信息架构

独立主导航“小说制片”，项目列表与项目工作区。项目内提供故事/设置、剧本、资产、分镜、任务与成片五个视图。阶段条始终显示当前流程以及下一步。现有图像、视频和定稿画布继续可用。

项目配置包括小说原文、画风、画幅、编剧语言模型、参考图生图模型、视频模型、并行数（1–3）和请求次数上限。小说先限制为 24000 字，单章自动拆成 1–6 集，每集最多 60 镜。超过范围明确要求拆章，不静默截断。

## 数据与流程

1. 解析：语言模型提取人物、场景、道具、特效；每项有固定 ID、别名、原文依据、外观锁定信息、定稿提示词。规划每集故事范围与结尾。
2. 编剧：逐集生成动作、对白、景别、静态生图提示词、动态视频提示词和显式资产引用。每集镜头时长合计严格为 120 秒，单镜不超过当前模型时长上限。
3. 自动审校：逐集检查人物/服装/道具一致性、动作可执行性、静态与动态提示词分工。保留审校前后版本与修改说明。结构错误自动修复至多两次；超限暂停。
4. 剧本审核：展示审校后的完整剧本与资产描述，可修改后重新审校，再审核通过。
5. 资产生成：共用资产各生成一张，作为候选。人物使用面部与正侧背设定板；场景、道具、特效独立参考。
6. 定稿审核：查看全部候选，允许替换为本机上传图片或重新生成单项。确认后冻结资产版本与图片 ID。
7. 分镜：只传入各镜头引用的定稿资产（最多 8 项），并行生成单张独立画面。自动产物标记为未人工视觉验收。
8. 二次审校与视频：分镜完成后，语言模型根据已有静态画面描述复核视频提示词，只允许修改视频提示词，程序锁定所有其他镜头字段。这不是自动看图验收。随后逐镜使用分镜图作为首帧；接口只有参考图能力时使用参考图。按模型有效档位请求，可为剪辑时长取更长档位，展示实际请求秒数。
9. 合成：所有镜头保存后，按集顺序本机合成 120 秒 MP4。原音轨保留，无声片段补静音；片段不足时失败，不用长静帧伪装两分钟。

每个任务都保存项目 ID、阶段、实体/集/镜 ID、请求回执和引用快照。SQLite 新增 novel_projects 表，不改写旧项目。事务内同时写任务和调度回执，已交接但状态不明绝不自动再 POST。重启沿用已有平台 ID 查询。

## 自动纠错的边界

语言模型负责文本和提示词审校，不凭空宣布画面一致。程序负责 JSON、ID、引用、时长、能力与次数校验。生成质量仍受模型影响；当前实现不宣称自动识别人脸漂移、动作变形、配音准确性。暂不单独生成配音、口型或字幕，保留剧本对白供原生有声视频模型及后续制作使用。

暂停阻止后续提交，已经提交的平台任务仍完成并保存。请求次数上限是硬限制，不等同费用预算；平台单价不明时不显示虚构金额。平台错误暂停队列，查询原任务与重试保存不重发生成。已确认失败任务可由用户单项重试并计入次数。

## 验收

- 缺少语言/参考生图/首帧或参考视频能力时提交前提示。
- 全流程模拟：小说解析 → 分集 → 自动审校 → 两次审核 → 资产/分镜/视频 → 分集合成。
- ID 不存在、非法时长、时长总和非 120、错误 JSON 触发修复且有上限；不向模型输出暴露密钥。
- 审核前不调用下一阶段媒体模型；替换资产后后续只使用最终图片。
- 并行上限、重复点击、重启交接、失败暂停、次数上限不会产生隐式重复收费。
- 历史数据保留；原工作台回归；真实收费模型和视觉质量另行以用户实际章节验收。

## 交付范围

本次实现上述本机闭环和可追踪任务，不升级成云端多人服务。小说原文和图片仅存本机；点击开始后，相关内容会发送至项目所选模型。导出项目计划不含 API Key，也不打包图片；跨电脑迁移仍需完整本机 data 目录。
