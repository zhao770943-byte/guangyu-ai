# 模型请求与系统代理

3.2.1 起，外部 HTTPS 模型请求默认使用电脑的代理配置，无需为每个厂商单独添加代理。目录读取、生成请求和任务查询共用路由；生成任务不会因网络失败自动再次提交。

## 路由规则

1. localhost、127.0.0.0/8、IPv6 回环始终直连，保护本机模型与工作台控制。
2. `data/provider-network.json` 中为该域名配置的本机 HTTP 代理优先，仍遵守系统的代理例外规则。
3. 其他外部 HTTPS 地址使用 Python 标准代理发现：环境变量配置优先，否则读取 Windows 当前用户的手动系统代理。HTTPS 使用 `HTTPS_PROXY`／`https_proxy`，`NO_PROXY`／系统例外列表指定的地址直连。
4. 没有可用代理配置时直接连接。代理连接失败时保留错误，不切换线路重发付费请求。

Windows 手动代理每次请求重新读取。代理客户端更换端口后，下一次请求使用新配置；环境变量由工作台进程继承，外部修改环境变量后需重启服务。首次安装本次代码修复也需要安全重启。

当前使用 HTTP／HTTPS 代理，不执行 PAC 自动配置脚本，不适配 SOCKS。代理软件只有 SOCKS 端口时，请启用 HTTP 或混合端口。TLS 仍校验目标证书，鉴权请求仍拒绝重定向。

## 可选：指定域名线路

多数用户无需创建此文件。需要特定厂商走指定端口时，在本安装的 `data/provider-network.json` 中写入：

```json
{
  "use_system_proxy": true,
  "https_proxy_by_host": {
    "api.example.com": "http://127.0.0.1:7890"
  }
}
```

显式路由只精确匹配域名，不匹配其子域名。此配置保留原约束：仅接受回环 IP 上的 HTTP 代理端口，不含用户名、密码、路径、查询参数。未命中的厂商继续使用系统代理；设置 `use_system_proxy: false` 可让未命中的厂商直连。配置无效时明确失败，不静默换线路。

此配置不能放 API Key。保存的模型密钥继续由 DPAPI 管理。工作台不修改 Windows 的全局代理设置。

## 修复与验收

| 原问题 | 新行为 | 检查方式 |
| --- | --- | --- |
| 未配置域名路由时强制直连 | 默认读取系统代理 | 模拟配置与真实本机 CONNECT 代理 |
| 系统代理误接管本地模型 | 回环始终直连 | IPv4、IPv6、localhost 与无例外列表测试 |
| 切换代理后仍用旧端口 | 每次请求读取设置 | 同一处理器前后切换端口 |
| 代理故障重复生成或泄露密钥 | 不重新提交，目标鉴权只在 TLS 隧道内发送 | 目录与生成调用各一次 CONNECT，隧道失败不带目标 Authorization |

连通性和账号权限分开验证。无密钥 GET 得到 401 说明服务端已响应，不能证明 API Key 有效或有余额。本机回归只调用隔离模拟服务，不进行付费生成。

本页覆盖供应商 API 请求；作品库下载外部媒体仍保留独立的地址校验和保存规则，不放宽内网下载限制。
