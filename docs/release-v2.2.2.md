# 光屿 AI v2.2.2

本次更新修复了语言模型被误配置为图像模型后，请求错误生图接口的问题。旧版本虽将 `MiniMax-M3` 识别为答疑模型，界面仍允许改成图像用途，后端也没有阻止这种错配，因而可能向 `/images/generations` 提交请求并收到 404。

## 修复内容

- 接入向导根据已知模型的输出能力禁用不支持的用途。能理解图片或视频的语言模型，不会因此被视为生图或生视频模型；未知型号仍需按平台文档确认用途。
- 旧错配连接显示“用途需修正”，保留在管理表格中，修正前不进入生成模型列表。编辑并选回受支持的用途后可保存继续使用。
- 后端在保存连接和构建任务请求时校验模型用途，已知错配会在发出生成请求前被拒绝。更新保留密钥与历史记录，不会重发此前失败的生成请求。
- MiniMax 中国区文生图文档列出 `image-01`、`image-01-live`，国际站文档目前只列出 `image-01`；它们使用专用 `/image_generation` 请求与响应结构。本版需配置自定义 JSON 映射，没有新增 MiniMax 原生图像适配器，也不会默认将其当作 OpenAI Images 使用。
- 404／405 错误会显示经过过滤的请求方法与相对路径，帮助核对模型用途、接口协议和请求路径；错误提示不包含查询参数或密钥。

`MiniMax-M3` 应配置为 **AI 助手 → OpenAI Chat Completions**。如果已有连接提示用途错误，在“模型接入”点击“编辑”并修正；基础地址不变时可留空 Key 复用原密钥。详细协议边界见 [MiniMax 接入说明](https://github.com/zhao770943-byte/guangyu-ai/blob/v2.2.2/docs/providers.md#minimax-模型用途与接口)。

## 使用与升级

下载本 Release 的 `GuangyuAI-v2.2.2-windows-x64.zip`，完整解压后运行 `GuangyuAI.exe`，保留配套 `_internal/`。Windows x64 便携版无需预装 Python。

升级前等待任务结束，使用旧目录中的停止脚本关闭服务并备份完整 `data/`。将新版解压到新目录，复制自己的 `data/` 到新 EXE 旁再启动；不要混搭新旧依赖目录或同时让两个实例读写同一份数据。详情见 [数据与维护](https://github.com/zhao770943-byte/guangyu-ai/blob/v2.2.2/docs/data-and-upgrades.md)。
