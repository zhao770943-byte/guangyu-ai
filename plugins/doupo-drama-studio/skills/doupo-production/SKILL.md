# 光屿连续漫剧制作

以用户最近确认的作品版本为起点。先读取本机项目与任务，再判断缺什么；不能把历史“已接受”当作新版本通过。不要从头重做已合格环节。

## 开始前读什么

1. 定位光屿运行目录、数据目录和项目；查看 phase、paused、version、films、最新任务、制作手册。用只读 `scripts/audit_project.py` 快速筛选。
2. 首次制作斗破项目，读 [第一集案例](references/episode-one-lessons.md)。这是用户定制改编，不是小说事实库。
3. 正在做镜头或声音时，读 [连续性与声音标准](references/continuity-and-audio.md)。
4. 需要更新本机记录或恢复失败任务时，读 [工作台协议](references/local-workbench.md)。不依赖旧端口、旧模型 ID、旧余额或旧 API 路径猜测能力。

## 一次制作怎么推进

先形成这次可交付范围：某集、某组镜头或某个声音修复。记录上一接受版本、问题、拟修改项、预计调用次数。用户既有授权继续有效；若当前授权范围不清，先完成不收费的检查和具体方案再询问缺失信息。不要每个小步骤重新要许可，也不要把过往充值当作无限重试授权。

**剧本**：对照用户提供的章节，列人物/道具/场景/特效；重要台词、姓名、段位与事件顺序逐项核对。原创补充写入改编记录。两分钟是节奏目标，不用静止画面凑满模型时长。为每镜写“事件→反应→选择”，标记入场、靠近、接触、结果、退场和邻镜关系。

**定稿**：先找用户已选的动漫参考，绑定人物与服装；建立同一场景的平面站位、道具关键细节和人群组。看实际图片，不依据模型文本评价自动判合格。关键道具要有近景定稿。继承上一集接受的定稿；换版必须留记录。

**分镜**：生成一张图只表现一个明确时刻。每镜填写首帧、动作节拍、镜尾、视线/方向、人群调度、衔接、禁止动作和声音方式。打开本镜与邻镜；核对七项：人物、道具、空间、人群、视线、动作、衔接。图片/定稿/约定变更后重新审核受影响镜头。不能自动批量勾选或伪造已看图。

**视频**：只提交当前已审且无阻塞问题的镜头，先做少量代表性镜头再扩大并发。模型支持的参考、首尾帧、时长、分辨率和声音需从当前连接确认。保留原任务 ID；超时先查询，下载失败先保存原结果，不立即重复付费。语言模型润色不能改掉已定动作、站位和资产。

**逐镜验收**：实际播放，再辅以抽帧。分别判断稳定性、动作、剧情推进、时长、设计。给每项证据和具体时间点，保存采用区间；静止首帧或 HTTP 成功不等于合格。只修有问题的镜头，不连带覆盖接受版本。模型输出 15 秒，可只取有效的几秒；对白不为凑时长拉伸变调。

**声音与交付**：锁定角色试听版本、发音词典、情绪与停顿；一次报幕姓名只念一次。逐句试听并对画面检查口型。对白、环境和音乐分轨，转场与片尾听完；不能仅通过响度数字宣称好听。完整审片后记录当前成片 ID、素材清单和版本；公开发布是另一个动作，依用户授权执行。

## 输出与持续记录

更新项目制作手册：已通过版本、未通过项、修复依据、下一步、实际调用次数。保留失败结果和历史用于诊断，但作品库仅展示成功作品。交付至少包括当前成片/审片入口、采用版本、未解决问题和检查范围。没有实际试听或观看就明确标记待审。

该 Skill 不把具体声优姓名、模型品牌或长提示词当作质量保证。接受的是实际样片。涉及平台或能力变更时查当前官方资料，优先利用现有已接入模型。
