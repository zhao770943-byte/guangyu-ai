# 光屿工作台实现

把具体制作失败转成可测试的产品行为，不只添加说明文字、更多表单或全局样式覆盖。与 $doupo-production 配合时，制作规则来自真实案例，实际实现以当前代码为准。

## 先定位和设计

1. 找源码目录、运行目录、DATA目录、服务实例及启动方式；检查 Git 状态与 AGENTS。源代码与运行文件可能不同，先比对。读取必要文件，不把密钥、原文、SQLite打印出来。
2. 列“失败→新行为→验收”表，确认本轮边界，在项目 docs 保存设计。已有明确授权就继续实现；缺失条件可边做独立工作边问。
3. 把功能安排在同一项目内：总览、剧本、资产、分镜、视频验收、声音、交付。各区职责分开，主要动作只有一个，不迫使用户来回跳栏目。更大的字、少量必要说明、主次按钮有色差；已有专业控件能复用就复用。
4. 以具体版本记录审核，模型完成与人工/实际视听验收分开。UI按钮禁止只是提示；后台也要拦截错误版本提交。

## 实现约束

先读 [系统边界与接口](references/implementation-map.md)。模块名可能变化，搜索确认后改。

- 保持已接受的资产、成片、暂停状态、请求收据与历史；schema变化使用兼容增量字段。
- 模型配置仍采用现有厂商、能力、字段映射与密钥存储。六AI分别做导演、编剧、定妆、灯光、运镜、监管；不另建一套重叠模型配置。
- 每次写入使用项目版本与request_id，失败验证不能留下半个修改。
- 分镜审核绑定图像像素、定稿引用、镜头事实、动作约定与邻镜；新视频提交前再次核对。
- 配音方向/词典是制作资料，不能标成已经自动执行的TTS能力。后期音轨/口型/采用区间需有实际媒体证据。
- 请求次数上限不是金额上限。不要显示推测账单；失败先查询原任务，下载失败不重新生成。
- 表单输入在轮询时不能丢失，失败后能继续编辑；新旧项目和小屏宽度都要检查。

## 验证与上线

1. 使用临时存储和模拟dispatch，验证换图失效、绕过UI仍被阻止、幂等、版本冲突、旧流程兼容。不能用用户余额跑测试。
2. JS语法/单测之后，实际打开本机页面，检查旧项目、新项目、分镜邻镜、声音、交付和窄屏。DOM或HTTP成功不能替代渲染检查。
3. 把本轮实际改动的运行文件备份后部署，不清空数据，不提交与本轮无关改动。使用现有受管启动方式。服务重启前查正在运行的任务，不能强杀在生成的项目。
4. 部署后确认 health实例、当前项目状态/成片未变、页面可用。插件/Skill同样验证清单、路径、脚本运行、安装回执。
5. 交付说明改了什么、验证了什么、没覆盖什么，附设计与主要文件；未经实际视听测试不得宣称配音/画面“质量通过”。

如仅构建本地改造，不擅自发布GitHub或发布视频。授权已包含的可逆操作继续完成，不人为加审批环节。
